# Problems & Improvements — Rent Control App

> Generated by codebase audit · 2026-03-22
> Stack: Expo / React Native (TypeScript), React Hook Form + Zod, Axios, i18next

---

## Critical Issues

These are bugs or security gaps that need to be addressed before production.

### 1. No Authentication
**File:** `src/core/api/client.ts` — line 7
Every API request is sent without an Authorization header. There is a TODO comment acknowledging this, but no implementation exists. Anyone who can reach the API can read or modify all data.
**Fix:** Implement an auth context (token storage with `expo-secure-store`), add the `Authorization: Bearer <token>` header to the Axios instance, handle 401 responses with a token-refresh interceptor, and add a login screen.

---

## Medium Priority

These are UX gaps, type-safety holes, and incomplete features that degrade the product experience.

### 2. `USE_MOCK_API` Hardcoded — Should Be an Env Variable
**File:** `src/core/api/mock.ts` — line 17
The flag is hardcoded as `false`. Toggling between real and mock API requires editing source code. This is also not accessible to CI environments.
**Fix:** Replace with `process.env.EXPO_PUBLIC_USE_MOCK_API === 'true'` and document it in `.env.example`.

---

### 3. Incomplete Mock Data — Missing Renter Fields
**File:** `src/core/api/mock.ts` — renter records with IDs 3 & 5
These records are missing `number_of_payments` and `payment_type` fields, creating an inconsistent dataset. Components that render those fields will silently show nothing for some renters.
**Fix:** Fill in all optional-but-commonly-used fields in the mock dataset to reflect realistic records.

---

### 4. RTL: Unicode Mark Breaks Mixed Hebrew/English Text
**File:** `src/core/context/LanguageContext.tsx` — lines 37, 52–67
The `\u200F` (Right-To-Left Mark) is prepended to all placeholder strings. This breaks inputs that contain numbers or English words alongside Hebrew text (e.g., an address field). Additionally, `marginLeft` / `marginRight` values in components are never swapped for RTL, so spacing is mirrored incorrectly.
**Fix:** Use CSS `direction: rtl` at the container level instead of injecting Unicode marks into individual strings. Audit all components for hardcoded left/right margins and convert them to `marginStart` / `marginEnd`.

---

### 5. Enum Fields Accept Any String in Validation Schemas
**Files:** `src/features/renters/validation/renterValidation.ts`, `src/features/properties/validation/propertyValidation.ts`
Fields like `paymentType`, `paymentFrequency`, `insuranceType`, and `propertyType` are validated as plain strings rather than Zod enums. Invalid values (e.g., a typo or a value not in the dropdown) pass validation silently and get sent to the backend.
**Fix:** Replace `z.string()` with `z.enum([...])` for all fields backed by a fixed set of options. Mirror the enum values from `src/shared/types/index.ts`.

---

### 6. Supplier Email Not Validated
**File:** `src/features/suppliers/validation/supplierValidation.ts` — line 8
The email field accepts any string. An invalid email format passes validation and gets stored.
**Fix:** Add `.email()` to the Zod schema for the supplier email field.

---

### 7. Hardcoded English Error Message in Supplier Validation
**File:** `src/features/suppliers/validation/supplierValidation.ts` — line 17
The "at least one category required" error message is a hardcoded English string. It will not change when the app is in Hebrew mode.
**Fix:** Use `i18n.t('validation.atLeastOneCategory')` and add the key to both `en.json` and `he.json`.

---

### 8. Lease Amount Allows Empty String
**File:** `src/features/renters/validation/renterValidation.ts` — line 34
Lease year amounts use `optionalNumericString`, which allows empty values. A lease year with no amount is meaningless data.
**Fix:** Require at least one lease year to have a non-empty, positive amount, or remove the entry entirely when the user leaves it blank.

---

### 9. Parking Numbers — No Format Validation
**File:** `src/features/properties/validation/propertyValidation.ts` — line 33
Parking numbers accept any string, but the app displays them as a comma-separated list. Garbage input (e.g., `"abc, , !"`) passes validation.
**Fix:** Add a regex or `.refine()` check: each segment between commas must be a non-empty alphanumeric token.

---

### 10. Numeric Fields Accept Negative Values
**File:** `src/features/properties/validation/propertyValidation.ts` — lines 6–21
Purchase price, property tax, house committee fees, and other monetary fields have no minimum value check. A user can submit `-999999` as a purchase price.
**Fix:** Add `.refine(n => n >= 0, 'Must be a positive number')` after `Number()` conversion in the `optionalNumericString` helper.

---

### 11. NaN Amounts Silently Become 0 in Transaction Summary
**File:** `src/features/transactions/screens/TransactionsListScreen.tsx` — lines 85–98
When a transaction has a non-numeric or null amount, the `reduce` that calculates revenue/expense totals converts it to `0` without any warning. The summary line shows an incorrect total.
**Fix:** Filter out or flag transactions with invalid amounts before summing, and surface a warning if any records are skipped.

---

### 12. Router Type Casts (`as any`) Throughout the App
**Files:** `TransactionsListScreen.tsx` line 106, `PropertiesListScreen.tsx`, `RentersListScreen.tsx`, and others
`router.push('/transactions/add' as any)` bypasses Expo Router's typed routes. If a route is renamed or removed, the error is invisible at compile time.
**Fix:** Enable Expo Router's typed routes feature (`"experiments": { "typedRoutes": true }` in `app.json`) and remove all `as any` casts.

---

### 13. No Search Debounce
**Files:** All list screens with search inputs
Every keystroke triggers a new API request (or context filter). On slow connections this causes a flood of requests and potentially renders stale results out of order.
**Fix:** Debounce the search input by 300–400ms using `useDebounce` or a `setTimeout`/`clearTimeout` pattern.

---

### 14. No Pagination
**Files:** `src/features/properties/context/PropertyContext.tsx`, `src/features/renters/context/RenterContext.tsx`
All properties and renters are fetched in a single request. As the dataset grows this will degrade performance and eventually hit API limits.
**Fix:** Add `page` / `limit` query parameters to list endpoints and implement infinite scroll or "Load More" in list screens.

## Low Priority / Code Quality

These are maintainability and polish issues that don't block functionality today but will slow down development over time.

### 15. `hasRenters` Flag Computed But Never Used
**File:** `src/features/properties/context/PropertyContext.tsx` — line 42
`hasRenters` is added to each property object during enrichment but is not rendered in any screen component. It's dead computation.
**Fix:** Either use it (e.g., show an "Occupied" badge on `PropertyCard`) or remove the enrichment step.

---

### 16. No Error Boundaries
The app has no React error boundaries. A runtime error in any component will crash the entire app and show a blank white screen with no recovery option.
**Fix:** Wrap the root layout with an `ErrorBoundary` component (or use `expo-error-reporter`) that shows a friendly "Something went wrong" screen with a "Restart" button.

---

### 17. No Tests
There are zero test files in `src/`. No unit tests for validation schemas, no integration tests for API layer, no component snapshot tests.
**Fix:** At minimum, add unit tests for all Zod validation schemas (they are pure functions and easy to test). Add API layer tests against a mock server using `msw` (Mock Service Worker).

---

### 18. `.env` File Committed to Repository
The actual `.env` file (containing the real API base URL) appears to be tracked by git. Only `.env.example` should be committed.
**Fix:** Add `.env` to `.gitignore` immediately. Rotate any sensitive values if real credentials were ever stored there.

---

### 19. No Skeleton/Shimmer Loading States
When data is loading, most screens show a simple spinner or nothing at all. This makes the app feel slow and unpolished.
**Fix:** Use `react-native-skeleton-placeholder` or implement shimmer-style placeholder cards for lists while data loads.

---

### 20. No Accessibility Labels on Icon Buttons
Icon-only buttons (FAB, tab bar items, action icons) have no `accessibilityLabel`. Screen reader users cannot determine their purpose.
**Fix:** Add `accessibilityLabel` and `accessibilityHint` props to all icon-only interactive elements.

---

### 21. Language Change Requires App Restart
**File:** `src/core/context/LanguageContext.tsx`
Switching between Hebrew and English calls `Updates.reloadAsync()` (or an equivalent restart). This is a jarring experience.
**Fix:** Use React Native's `I18nManager.forceRTL()` with a coordinated context update to flip RTL direction at runtime without a full restart (requires all layout code to use `marginStart`/`marginEnd` and `Start`/`End` variants).

---

## Missing Features

These are features that appear partially started or implied by the architecture but are not yet implemented.

### 22. Property Image Upload Not Implemented
**File:** `src/features/properties/hooks/usePropertyForm.ts`
`imageUri` is managed in local state and sent as a string to `createProperty`/`updateProperty`, but the `POST /properties/:id/image` endpoint (which accepts `FormData`) is never called. Images are not actually uploaded.
**Fix:** After a successful create/update, if `imageUri` is a local file URI, call the image upload endpoint with `FormData` and refresh the property to get the server-returned URL.

---

### 23. Transaction Date-Range Filtering Not Implemented
**File:** `src/features/transactions/screens/TransactionsListScreen.tsx`
The API contract documents `date_from` / `date_to` query parameters, and the UI has filtering affordances, but date-range filtering is not wired up.
**Fix:** Add a date range picker to the filter UI and pass `date_from` / `date_to` to the `getTransactions()` API call.

---

### 24. Authentication Flow
There is no login screen, no token storage, and no session management. The app assumes an already-authenticated user.
**Fix:** Implement a full auth flow: login screen → store JWT in `expo-secure-store` → inject token in Axios interceptor → handle token expiry with refresh → redirect to login on 401.

---

### 25. Optimistic Updates
All mutations (create, update, delete) wait for the full server round-trip before updating the UI. On slow connections, the app appears frozen.
**Fix:** Implement optimistic updates: immediately apply the change to local context state, then reconcile with the server response (or rollback on error).

---

### 26. Offline / Mock Mode Is Incomplete and Manual
**File:** `src/core/api/mock.ts`
`USE_MOCK_API` must be hand-edited in source code, and even then image upload and several other endpoints have no mock implementation. The app cannot be meaningfully demonstrated or tested without a live backend.
**Fix:** Complete the mock implementations for all endpoints and make the toggle an environment variable. Consider using `msw` for a more robust and realistic mock layer.
